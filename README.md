# 智能收作业系统（离线版）

基于 **ESP32-S3 + PN532** 的课堂作业登记器：学生把贴了 NTAG 标签的作业本往读卡器上一放，屏幕立刻登记，全程离线，数据存在 SD 卡里断电不丢。

> 早先版本只是个"读卡显示 UID"的演示器，现在是一个完整的收作业工具。老版本的功能（读卡 / NTAG 写卡）都保留了。

---

## 功能

- **刷卡登记** —— 作业本贴上 NTAG 标签，刷一下即登记，屏幕显示姓名、提交结果和全班进度条
- **专属编号** —— 每个学生自动发一个编号（`0001` 起），既存名单也写进卡片，刷卡时两边核对
- **防拿错卡** —— 卡里编号和名单对不上会当场拦下，并告诉你是谁的卡
- **未交名单** —— 按 C 键随时翻看谁还没交，分页显示
- **多次作业** —— 最多 30 次，全部交齐后自动进入下一次
- **断电记忆** —— 名单和提交记录都写成 CSV 存在 SD 卡里，拔电重启接着用
- **中文双字库** —— SD 卡放 `font.vlw`（抗锯齿）优先，不插卡自动回退内置 16×16 点阵
- **写卡模式** —— 批量给空白标签发编号，或给已登记的卡补写

## 硬件接线

### ST7789 TFT (240×240) —— SPI2 (FSPI)

| TFT Pin | ESP32 Pin |
|---------|-----------|
| SCK     | 4         |
| MOSI    | 5         |
| RST     | 6         |
| DC      | 7         |
| CS      | 10        |
| BLK     | 13        |

### PN532 (SPI 模式) —— 软件 SPI

| PN532 Pin | ESP32 Pin |
|-----------|-----------|
| SCK       | 17        |
| MISO      | 18        |
| MOSI      | 8         |
| SS        | 3         |
| IRQ       | 11        |
| RST       | 12        |

> PN532 模块上的拨码开关要拨到 SPI 模式（SEL1=0，SEL2=1）。

### SD 卡 —— SPI3 (HSPI)

| SD Pin | ESP32 Pin |
|--------|-----------|
| SCK    | 42        |
| MISO   | 41        |
| MOSI   | 40        |
| CS     | 39        |

> **注意**：屏幕和 SD 卡必须走不同的 SPI 主机。代码里屏幕用 `SPI2_HOST`、SD 卡用 `SPI3_HOST`，如果改成同一个主机会因为两边各自调用 `spi_bus_initialize()` 互相冲突。

### 按键（另一端接 GND，内部上拉）

| 按键 | ESP32 Pin | 功能 |
|------|-----------|------|
| A    | 14        | 短按 = 开新作业 / 确认；**长按 1 秒 = 清空全部记录** |
| B    | 15        | 上翻页 / 取消 |
| C    | 16        | 切换到未交名单 / 下翻页 |

## 编译烧录

1. Arduino IDE 开发板选 **ESP32S3 Dev Module**（参照根目录 `参数.xlsx` 的完整配置：16MB Flash、QIO 80MHz、USB CDC On Boot 启用等）
2. 打开 `sketch_sep6a.ino` 编译烧录
3. 打开 **串口监视器**，波特率 **115200**

> `font_cn.h` 约 770 KB 源码 / 120 KB flash，编译会慢一点，属正常现象。

## 使用流程

### 第一次：登记学生

1. SD 卡插好，上电。检测不到名单会自动进入**登记模式**
2. 依次刷每个学生的贴纸，串口监视器输入 `name=张三`
3. 全部录完输入 `d` 保存退出

串口命令（登记模式下）：

| 命令 | 作用 |
|------|------|
| `name=名字` | 给刚刷的贴纸命名并加入名单 |
| `d` | 完成登记，保存到 SD 卡 |
| `list` | 打印当前名单 |
| `clear` | 清空名单 |

### 日常：收作业

| 操作 | 效果 |
|------|------|
| 刷作业本 | 登记，屏幕绿字"提交成功" + 进度条 |
| 重复刷 | 黄字提示"这次已经交过了"，不会重复计数 |
| 刷陌生卡 | 红字提示"未登记的卡"，并显示 UID |
| 按 C | 查看未交名单，B/C 翻页 |
| 全部交齐 | 自动跳到下一次作业 |
| 按 A | 确认后手动开新作业 |
| **长按 A** | 清空所有作业记录（名单保留） |

### 串口模式切换（任何时候）

| 命令 | 作用 |
|------|------|
| `s` | 进入登记模式 |
| `w` | 进入写卡模式（发编号 / 补写） |
| `r` | 回到刷卡登记 |

## 硬件没到齐怎么先跑起来

按键和读卡器都不影响开机：**PN532 检测不到时不再卡死**，而是进入「无卡模式」——屏幕、中文字库、SD 存档、名单管理全部正常工作，只是读不到真实卡片。

所有按键操作都有对应的串口命令，没按键时直接敲命令就行：

| 按键 | 串口命令 | 效果 |
|------|----------|------|
| A（短按） | `n` | 开新作业 / 确认 |
| B | `u` | 上翻页 / 取消 |
| C | `m` | 未交名单 / 下翻页 |

模拟刷卡（读卡器没到时用）：

```
sim=张三          # 模拟刷张三的卡，走完整登记流程
sim=04 A2 3F 1B  # 模拟刷指定 UID
sim?             # 模拟刷一张未登记的卡
```

其它命令：`s` 登记模式、`w` 写卡模式、`r` 回刷卡界面、`probe` 读卡器自检、`h` 帮助。

## 读卡器到货后的首次上机检查

按顺序做，每一步都有明确的"对了应该看到什么"。

### 1. 拨码开关拨到 SPI（最容易翻车的一步）

PN532 模块上两个拨码开关，要拨到 **SEL1=0 / OFF，SEL2=1 / ON**。
不同厂家的丝印不一样，如果板子上标的是 `SEL0/SEL1`，按这个表对：

| 想要 | SEL0 | SEL1 |
|------|------|------|
| SPI（我们要的） | 0 | 1 |
| I2C | 1 | 0 |
| HSU 串口 | 0 | 0 |

拨完**必须断电重上电**才生效。

### 2. 接线

最少接 6 根就能验证（`IRQ` 本工程没用到，可以先不接）：

| PN532 | ESP32 |
|-------|-------|
| VCC   | 3.3V（板子带稳压的接 5V 也行，但**别两种同时接**） |
| GND   | GND |
| SCK   | 17 |
| MISO  | 18 |
| MOSI  | 8 |
| SS    | 3 |
| RST   | 12 |

> 这四根信号线走的是**软件 SPI**（库里按位模拟），所以任意 GPIO 都行，
> 不必是芯片的硬件 SPI 引脚。

### 3. 编译前先装依赖

`Adafruit_PN532` 会无条件 include `Adafruit_I2CDevice.h`。
库管理器里装 **Adafruit I2C Device**，否则报
`fatal error: Adafruit_I2CDevice.h: No such file`。

### 4. 看开机日志

烧录完打开串口监视器（115200），**正确的**输出是：

```
Init PN532...
PN532 F/W 1.6        <- 这行出现说明读卡器和拨码开关都对
```

如果看到的是
`WARN: PN532 not found - running WITHOUT reader`，
说明没连上，回到第 1 步重新确认开关和接线。

### 5. 用 probe 确认能读到卡

串口敲 `probe`，它会连续扫 10 秒，把卡放上去：

```
probe: 连续扫描 10 秒，把卡片放上去...
  卡 #1 UID: 04 A2 3F 1B  (4 字节)  卡内无编号（空白卡 / 非本系统）  名单:未登记
probe 结束，共识别 1 张卡
```

一张都没读到时会直接列出排查清单（开关 / 接线 / 卡片类型）。

> 只认 **ISO14443A** 的卡：NTAG213/215/216、Mifare 系列都行；
> **身份证、门禁卡、银行卡读不到**（那些是别的协议或做了加密）。

### 6. 跑通完整流程

```
s            进登记模式
（刷卡）     串口打印 UID，提示输入姓名
name=张三    自动分配编号 0001，写入卡片并读回校验
name=李四    编号 0002，依此类推
d            登记完成，回到刷卡界面
（刷卡）     登记作业，屏幕显示 [0001] 张三 提交成功
m            看谁还没交
```

写进 SD 卡的 `/roster.csv` 长这样：

```
# UID_HEX,SID,NAME
04 A2 3F 1B,1,张三
```

### 7. 验证防拿错卡

把两张卡互换着刷一次，应该弹「编号不符」并提示是哪位同学的卡。。

硬件到齐后接上即可，串口命令和按键可以混用，不需要改代码。

## 专属编号与写卡

每个学生有一个**专属编号**（1~50，按登记顺序自动分配，显示成 `0001` 这样），
这个编号既存在名单里，也**写进卡片**。刷卡时两边一起核对，
能当场抓出「拿错卡」「换卡」的情况。

### 卡片里存了什么

只占 2 页，写入和校验都很快：

| 页 | 内容 |
|----|------|
| 第 8 页 | `'R' 'F' 'I' 'D'` 魔数，一眼认出是我们的卡 |
| 第 9 页 | 版本号 \| 编号高字节 \| 编号低字节 \| 校验和 |

校验和是前 7 个字节按位异或，卡片写坏或读到脏数据时会直接被拦下。

| 型号 | 用户页范围 |
|------|-----------|
| NTAG213 | 4 ~ 39 |
| NTAG215 | 4 ~ 129 |
| NTAG216 | 4 ~ 225 |

### 怎么发号

**方式一：登记时自动写卡（推荐）**

串口 `s` 进登记模式，刷卡 → 输入 `name=张三`，
系统自动分配编号并**顺手把编号写进这张卡**，写完立刻读回校验。
一张卡一步搞定，不用再单独跑写卡模式。

**方式二：批量写卡 / 补写**

串口 `w` 进写卡模式，一张一张往上放：

- **没登记过的卡** → 自动分配下一个空闲编号并写入
- **已经登记过的卡** → 把它的编号重写回去（卡片蹭坏了、想补号时用）

写卡界面会显示"下一个将分配编号 00XX"，不用记自己数到哪了。

### 刷卡时的核对

UID 对上名单只是第一步，程序还会读回卡内编号再比一次：

| 情况 | 屏幕显示 |
|------|---------|
| 编号一致 | 正常记录提交，姓名上方显示 `[0007]` |
| 卡里是别人的编号 | `编号不符`，并直接告诉你是谁的卡 |
| 卡里没编号 | `卡里没有编号`，提示可能没写过 |

这种核对能防止别人替交作业——只拿卡不刷对不上的号会被拦下。

> ⚠️ **依赖提醒**：`Adafruit_PN532` 库会无条件 include `Adafruit_I2CDevice.h`，
> 即使你用软件 SPI 用不到 I2C 也一样。编译报
> `Adafruit_I2CDevice.h: No such file` 时，在库管理器里装一下
> **Adafruit I2C Device** 即可。

## 中文字库：vlw 优先，点阵兜底

两种方案会自动选择，**SD 卡上有 `/font.vlw` 就用 vlw**：

| 方案 | 条件 | 特点 |
|------|------|------|
| **SD 卡 vlw**（优先） | 卡根目录存在 `/font.vlw` | 8bit 抗锯齿灰度，观感最好；换字体/字号重新生成就行 |
| **内置点阵**（兜底） | 没插卡 / 卡上没有 `/font.vlw` | 16×16 点阵编译进 flash，任何情况都能显示中文 |

开机串口会打印用的是哪一套，类似：

```
Font: vlw loaded (/font.vlw), native line height=16, scale=1.00
Font: no font.vlw on card, using built-in bitmap (95 ASCII + 3788 CJK)
```

### ⚠️ 为什么放的是 .vlw 而不是 .ttf

LovyanGFX 的 TTF 解码器在官方仓库的**可选文件** `lgfx_ttffont.hpp` 里，
Arduino 库管理器装的发行版**没有它**。没有它时，库把所有字体文件一律按
VLW 格式解析（见 `lgfx_fonts.cpp` 里的 `#ifdef LGFX_TTFFONT_HPP_`），
往卡里塞 `.ttf` 只会加载失败或显示乱码。

`.vlw` 本来就是「用任意 TTF 在电脑上预渲染出来的字体文件」——
想换微软雅黑、思源黑体等任何字体，改一下生成脚本的 `--font` 参数即可，
效果等同于矢量字体。

### 生成字库

```bash
cd tools
pip install Pillow
python gen_font_cn.py --preview font_preview.png
# 或者直接写进 SD 卡：python gen_font_cn.py --vlw E:\font.vlw
```

脚本一次产出两个文件：

- `font.vlw`（约 900 KB）→ 拷到 SD 卡根目录
- `font_cn.h`（编译进 flash 的点阵兜底，约 120 KB flash）

字符集自动包含：ASCII + GB2312 一级汉字（3755 个）+ 常用标点 +
**扫描 `.ino` 源码里出现过的所有汉字**（以后改 UI 文案也不怕缺字）。
默认源字体 `C:\Windows\Fonts\simhei.ttf`，想换加 `--font` 参数；
字号默认自动选到 16px 行高以内，想指定用 `--size`。
生成后可以用 `verify_vlw.py` 离线渲染检查（它完全照抄库里的解析算法）：

```bash
python verify_vlw.py ../font.vlw vlw_check.png
```

## 代码结构

```

├── 引脚定义          屏幕 / PN532 / SD / 按键
├── 数据模型          Student 结构（uid + 编号 + 姓名）、提交位图 (50 人 × 30 次)

├── 绘图原语          fillRect / drawFastHLine / printCentered / printRight
├── UI 画面           刷卡 / 未交名单 / 登记 / 写卡 / 编号不符
├── 编号与写卡        nextFreeSid / writeCardSid / readCardSid（含校验和与回读核对）
└── loop()            状态机 + 串口命令解析
```

## 已知限制

- 写卡仅支持 **NTAG** 系列（Ultralight 协议），Mifare Classic 写卡暂未加入
- 编号是顺序号（1~50），中途删人不会重排编号，避免已发出的卡对不上
- 字库只收了 GB2312 一级汉字，姓名里出现生僻字会显示成方框
- 刷卡时每次都要读回卡片做编号核对，比只看 UID 慢约 30ms
